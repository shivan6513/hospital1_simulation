def simulate_python(n_days):
    """Simulate daily patient arrivals (10-50) for n_days using a Python loop."""
    arrivals = []
    for _ in range(n_days):
        arrivals.append(random.randint(10, 50))
    return arrivals

# Warm-up (avoids first-call overhead)
_ = simulate_python(100)

start = time.perf_counter()
arrivals_100 = simulate_python(100)
python_100_time = time.perf_counter() - start

print(f"Python  | 100 days | time = {python_100_time:.6f} s | "
      f"avg arrivals = {np.mean(arrivals_100):.2f}")

def simulate_numpy(n_days):
    """Vectorised: draw all daily arrivals at once."""
    return np.random.randint(10, 51, size=n_days)  # high is exclusive -> 10..50

sizes = [100, 1_000, 10_000, 100_000]
REPEATS = 5

results = []

for n in sizes:
    py_times = []
    for _ in range(REPEATS):
        t0 = time.perf_counter()
        py_arr = simulate_python(n)
        py_times.append(time.perf_counter() - t0)

    np_times = []
    for _ in range(REPEATS):
        t0 = time.perf_counter()
        np_arr = simulate_numpy(n)
        np_times.append(time.perf_counter() - t0)

    results.append({
        "Days": n,
        "Python time (s)": np.mean(py_times),
        "NumPy time (s)": np.mean(np_times),
        "Python avg arrival": np.mean(py_arr),
        "NumPy avg arrival": np.mean(np_arr),
    })

df = pd.DataFrame(results)
df["Speed-up (x)"] = df["Python time (s)"] / df["NumPy time (s)"]
df.round(6)

<h2 id="Findings">Findings¶</h2><p>1. Which is faster? NumPy is faster for large N. At 100 days the loop is comparable (or even faster) because of NumPy's fixed call overhead. From ~1,000 days onward NumPy wins, and by 100,000 days it is roughly 30–60× faster.</p> <p>2. Why does execution time change?</p>
  • Python loop: time grows linearly with N. Each iteration pays for the interpreter, a Python function call (random.randint), and a list append — O(N) Python-level operations.
  • NumPy: np.random.randint(..., size=N) runs the whole generation as one compiled C routine over contiguous memory, so the per-element cost is tiny and constant relative to Python. The result is a nearly flat slope.
<p>3. Do both produce similar average arrivals? Yes. With arrivals uniform over 10–50, the theoretical mean is (10+50)/2 = 30. Both implementations converge to ≈30 as N grows — differences at 100 days are just sampling noise, not bias.</p> <p>4. Practical takeaway Use a plain Python loop for small, readable, one-off simulations. Once simulating tens of thousands of days (or patients), switch to NumPy — the speed gain is enormous and averages remain correct.</p>
